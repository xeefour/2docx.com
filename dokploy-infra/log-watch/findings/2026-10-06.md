- ส่วนประกอบอื่นยังปกติดี: MongoDB primary `mongo-3:27017` (39ms), Valkey PONG (34ms), NATS stream JOBS ค้าง 1 ข้อความ/376 bytes (น่าจะเป็นงานที่ worker ควรดึงไปทำ), RustFS bucket 'documents' (52ms), 2docx docserver (48ms)
- สัดส่วนเหตุการณ์ Warn/Error/Fatal สูงสุดอยู่ที่ `docgen-gateway` (22 บรรทัด) และ `mongo-3` (12) — สอดคล้องกับภาพ worker ตาย + gateway พยายาม dispatch งานซ้ำ

## สิ่งที่ต้องทำ
1. ดูสถานะ/ล็อก worker ทันที
   ```
   docker ps -a --filter name=docgen-worker
   docker inspect docgen-worker --format '{{.State.Status}} exit={{.State.ExitCode}} since={{.State.StartedAt}}'
   docker logs --since=30m docgen-worker | tail -200
   ```
2. ถ้า restart ตัวเองล้มเหลวซ้ำ ลองรันด้วยตัวเองเพื่อจับ stacktrace สด
   ```
   docker rm -f docgen-worker && docker run --name docgen-worker <image:tag>
   ```
3. รีสตาร์ทเพื่อกู้สถานะ (หลังเก็บหลักฐานล็อกแล้ว)
   ```
   docker restart docgen-worker
   ```
4. ตรวจว่างานใน NATS ยังค้างอยู่ไหมหลัง worker กลับมา
   ```
   docker exec nats-box nats stream info JOBS
   docker exec nats-box nats consumer info JOBS docgen-worker
   ```
5. ดูเหตุการณ์ในช่วงเวลาที่ worker ตาย
   ```
   docker logs --since=1h docgen-gateway | grep -Ei 'worker|heartbeat|timeout|503'
   ```

## ข้อควรระวัง
- การ `docker rm -f` จะทำให้งานที่กำลังเรนเดอร์อยู่ (ถ้ามี) หายไป — ควรเช็ค NATS ก่อนว่ามี message ค้างหรือไม่ (ตอนนี้พบ 1 ข้อความ) เพื่อให้ worker ตัวใหม่ดึงงานต่อได้
- threshold 90 วินาที กับที่ตายจริง 1,275 วินาที ห่างกันมาก บ่งชี้ว่า worker อาจค้าง (deadlock/oom/รอ resource) ไม่ใช่ restart วนลูป — ต้องดูล็อกย้อนหลังให้ถึงจุดที่ heartbeat หยุด
- `/api/health` ตอบ 503 ตอนนี้เป็น **ผลลัพธ์** ไม่ใช่ต้นเหตุ — แก้ worker แล้วเส้นทางนี้จะกลับเป็นปกติเอง ไม่ต้องแตะ API
- ถ้าในล็อก worker เจอ OOMKilled ให้ตรวจ `--memory` ของ container และขนาด job ที่ค้างใน NATS (376 bytes เล็กมาก น่าจะไม่ใช่สาเหตุจาก payload)
- หลังกู้คืน ควรตั้ง alert เมื่อ heartbeat เกิน 2 เท่าของเกณฑ์ (เช่น >180 วิ) เพื่อจับกรณีค้างระยะสั้นก่อนถึง 90 วิ

# การตั้งค่า Carbone

คุณสังเกตถูกต้อง — ค่าใน log ตั้งแก้ได้ และการปรับให้ผลจริง

---

## จุดที่พบ

log ตอนเริ่ม container ระบุว่า:
```
- factories                   : 1
- maxGenerationTime           : 60000 ms (= converterFactoryTimeout)
```

เครื่องหมาย `=` หมายความว่า `maxGenerationTime` **ผูกกับ `converterFactoryTimeout`**
แปลว่าเป็นค่าที่ตั้งได้ ไม่ใช่ข้อจำกัดถาวร

ไฟล์ตั้งค่าอยู่ที่: `/app/config/config.json`

ค่าเริ่มต้น:
```json
{
  "port": 4000,
  "bind": "127.0.0.1",
  "factories": 1,
  "authentication": false,
  "jwtAudience": "carbone-ee",
  "templatePathRetention": 0,
  "maxDataSize": 62914560
}
```

---

## ค่าที่ปรับไว้

ไฟล์: `config/carbone-config.json`

```json
{
  "port": 4000,
  "bind": "0.0.0.0",
  "factories": 3,
  "authentication": false,
  "jwtAudience": "carbone-ee",
  "templatePathRetention": 0,
  "maxDataSize": 62914560,
  "converterFactoryTimeout": 300000,
  "instanceMaxFiles": 200,
  "instanceQueueSize": 10
}
```

| ค่า | เดิม | ใหม่ | หน่วย | ผลกระทบ |
|---|---|---|---|---|
| `converterFactoryTimeout` | 60000 | **300000** | มิลลิวินาที | เวลาสูงสุดต่อเอกสาร 1 ชิ้น: 60 วิ → **5 นาที** |
| `factories` | 1 | **3** | งาน | งานพร้อมกัน: 1 → **3 งาน** |
| `instanceMaxFiles` | ค่าเริ่มต้น | 200 | ไฟล์ | จำนวนไฟล์สูงสุดที่เก็บไว้ |
| `instanceQueueSize` | ค่าเริ่มต้น | 10 | งาน | ความยาวคิวรอ |
| `bind` | 127.0.0.1 | **0.0.0.0** | - | รับการเชื่อมต่อจากภายนอก container |

---

## ผลการทดสอบจริง

### เอกสารขนาดใหญ่

| เนื้อหา | เดิม (60 วิ) | ใหม่ (300 วิ) | ผล |
|---|---|---|---|
| 60 KB (71 หน้า) | ผ่าน 43.9 วิ | ผ่าน 44.5 วิ | เท่าเดิม |
| **100 KB (114 หน้า)** | **หมดเวลา** | **ผ่าน 175.4 วิ** | **ดีขึ้นมาก** |
| 200 KB | หมดเวลา | หมดเวลา 300 วิ | ยังไม่พอ |

**เอกสาร 100 KB ที่เคยทำไม่ได้ ตอนนี้ทำได้** และใช้เวลาเกือบ 3 นาที
ซึ่งยืนยันว่าขีดจำกัด 60 วิ เป็นตัวที่กำหนดจริง ไม่ใช่ปัญหาอื่น

### ประสิทธิภาพ (3 งานพร้อมกัน)

| ค่า factories | เวลาที่ใช้ |
|---|---|
| 1 (เดิม) | 25.9 วินาที |
| **3 (ใหม่)** | **9.4 วินาที** |

**เร็วกว่า 2.8 เท่า** สำหรับงานที่ส่งมาพร้อมกัน

### ผลกระทบต่อหน่วยความจำ

| ค่า factories | RAM ขณะประมวลผล |
|---|---|
| 1 | ~300 MB |
| 3 | ~490-650 MB |

ยังเหลือพอมากจาก 3.7 GB


### ค่าที่ควรพิจารณา

**`converterFactoryTimeout`**

| ค่า | เหมาะกับ |
|---|---|
| 60000 (60 วิ) | เอกสารสั้นเท่านั้น |
| 120000 (2 นาที) | เอกสารราชการทั่วไป |
| **300000 (5 นาที)** | **เอกสารยาว แนะนำ** |
| 600000 (10 นาที) | บันทึกประชุม รายงานประจำปี |

**ข้อควรระวัง:** ยิ่ง timeout นาน งานที่ค้างก็ยิ่งกินเวลานานขึ้น
ถ้าเอกสารหนึ่งค้าง 5 นาที ระบบก็จะไม่รับงานอื่นใน factory นั้น
(factories=3 จึงช่วยได้ เพราะมี 3 ช่องรอ)

**`factories`**

| ค่า | เหมาะกับ |
|---|---|
| 1 | ประหยัดหน่วยความจำ |
| 2-3 | **งานประมาณ 1-3 งานพร้อมกัน แนะนำ** |
| 5+ | งานหนาแน่น แต่ RAM ต้องมากพอ |

RAM ที่ต้องใช้โดยประมาณ: `factories × 200 MB` (สำหรับเอกสารภาษาไทย)

```powershell
docker logs carbone-thai 2>&1 | Select-Object -First 30
```

จะเห็นบรรทัดแบบนี้:
```
- factories                   : 3
- maxGenerationTime           : 300000 ms (= converterFactoryTimeout)
- maxDataSize                 : 62914560 bytes
```

**ถ้าค่าที่เห็นไม่ตรงกับ config** แปลว่า config ไม่ถูกโหลด
ให้ตรวจว่าไฟล์อยู่ที่ถูกที่และสิทธิ์ถูกต้อง

## เรื่องความปลอดภัยที่ยังต้องระวัง

config มี `"authentication": false` — นี่คือสาเหตุที่ **Carbone ไม่ตรวจ API Key**

| ค่า | ผล |
|---|---|
| `authentication: false` | ใครก็เรียกได้ (ค่าเริ่มต้น) |
| `authentication: true` | ต้องมี license / ระบบคีย์ — เป็นฟีเจอร์ Enterprise |

**ยังไม่ได้ทดสอบ** ว่า `authentication: true` ในเวอร์ชัน Community
จะใช้ได้หรือไม่ (อาจต้องซื้อ license)

**คำแนะนำ: ยังต้องมี API Gateway คุมสิทธิ์เอง**
ห้ามเปิดพอร์ต 4000 ออกสู่อินเทอร์เน็ตโดยตรง

## ข้อควรระวัง

1. **งานที่ค้างกินเวลาตาม timeout** — ถ้า timeout 5 นาที งานค้างหนึ่งงานจะกินเวลานี้
   ตั้ง `factories` ให้พอจะช่วยได้ เพราะงานอื่นยังทำต่อได้

2. **RAM เพิ่มตาม factories** — factories=3 ใช้ ~500-650 MB ถ้าตั้ง 5 อาจถึง 1 GB

3. **`bind: 0.0.0.0`** ทำให้ container รับการเชื่อมต่อจากภายนอก
   Docker Desktop ยังจำกัดการเข้าถึงจากเครื่องอื่นอยู่ แต่ถ้ารันบนเซิร์ฟเวอร์จริง
   ต้องใช้ firewall ปิดพอร์ต 4000

4. **ยังต้องแบ่งเอกสาร** — แม้เพิ่มเวลาเป็น 5 นาที เอกสาร 200 KB ก็ยังทำไม่ทัน
   เอกสารยาวมากควรแบ่งเป็นหลายฉบับอยู่ดี

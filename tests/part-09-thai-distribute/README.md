# ทดสอบการกระจายย่อหน้าไทย (thaiDistribute)

**ไฟล์ทดสอบ:** `หนังสือรับรองเงินเดือน.docx` (เอกสารราชการจริง)
**วันที่:** 29 กันยายน 2569

---

## สรุปสั้น

**LibreOffice (ซึ่ง Carbone ใช้แปลงเป็น PDF) ไม่รองรับ `thaiDistribute`**

ต้องใช้ค่า **`both`** (กระจายสองข้าง) แทน ซึ่งให้ผลลัพธ์กระจายสมบูรณ์กว่า

---

## ผลการทดสอบ

ทดสอบเนื้อหาจริง 301 ตัวอักษรไทย วัดระยะจากขอบขวาของแต่ละบรรทัด

| เวอร์ชัน | ค่า jc | บรรทัดที่กระจายเต็ม | เหลือขวาเฉลี่ย | ผล |
|---|---|---|---|---|
| A | ไม่ตั้ง (ค่าเริ่มต้น) | 2 / 3 | 7.1 จุด | ไม่ครบ |
| B | `thaiDistribute` | 2 / 3 | 7.1 จุด | **เท่ากับ A — ไม่มีผล** |
| C | `both` | **3 / 3** | **-0.2 จุด** | **สมบูรณ์** |

### ข้อสังเกตสำคัญ

**เวอร์ชัน A และ B ให้ผลลัพธ์เหมือนกันเป๊ะ** และ PDF มีขนาดเท่ากันทุกไบต์ (109,066 bytes)

แปลว่า `thaiDistribute` **ถูกเก็บไว้ในไฟล์ DOCX แต่ไม่มีผลตอนแปลงเป็น PDF**

ตรวจสอบแล้วว่าค่า `thaiDistribute` ยังอยู่ในไฟล์ผลลัพธ์ DOCX (3 ย่อหน้า)
แต่เมื่อแปลงเป็น PDF กลายเป็นเหมือนชิดซ้ายธรรมดา

---

## เหตุผลทางเทคนิค

Word แยกการตั้งค่าการจัดวางเป็น 2 ระดับ:

| ค่า | ความหมาย | LibreOffice รองรับ |
|---|---|---|
| `both` (justify) | ยืดระยะห่างระหว่าง**คำ** ให้เต็มบรรทัด | **ได้** |
| `distribute` / `thaiDistribute` | ยืดระยะห่างระหว่าง**ตัวอักษรทุกตัว** ให้เต็มบรรทัด | **ไม่ได้** |

`thaiDistribute` จะบีบระยะห่างระหว่าง*ตัวสะไทย* ให้เต็มพอดี ไม่ใช่ระหว่าง*คำ*
ซึ่งเป็นเอกสารแบบโบราณของ Word เวอร์ชันเก่า — LibreOffice ไม่รองรับ

**สำหรับงานเอกสารราชการ `both` เพียงพอและดีกว่า** เพราะการกระจายระดับคำ
อ่านง่ายกว่า ถ้ากระจายระดับตัวอักษร ตัวสะไทยจะหลุดออกจากกัน

## วิธีที่แนะนำ

### 1. ในแม่แบบ Word

ตั้งค่าย่อหน้าเนื้อหาด้วย
- **Microsoft Word:** หน้าแรก → ย่อหน้า → จัดวาง → **กระจายสองข้าง** (Ctrl+J)
- **LibreOffice:** จัดวาง → **ตรงเส้นทั้งสองข้าง** (Ctrl+J)

> ถ้าใช้ Word รุ่นเก่าที่มี "กระจายทั้งบรรทัด" — ให้เปลี่ยนเป็น "กระจายสองข้าง"
> ค่าเดิมจะไม่มีผลเมื่อผ่าน Carbone

### 2. เขียนโค้ดกำหนดเอง

```python
from docx import Document
from docx.enum.text import WD_ALIGN_PARAGRAPH

doc = Document("แม่แบบ.docx")
for p in doc.paragraphs:
    p.alignment = WD_ALIGN_PARAGRAPH.JUSTIFY   # = both
doc.save("แม่แบบ-แก้แล้ว.docx")
```

### 3. ระดับ XML (ถ้าต้องการยิงตรง)

```xml
<w:jc w:val="both"/>
```

## การตรวจสอบว่ากระจายถูกต้อง

ใช้สคริปต์ `measure_align.py` ที่วัดระยะจากขอบขวาจริง

```powershell
python measure_align.py "ผลลัพธ์.pdf" "ชื่อการทดสอบ"
```

**ตีความผล:**
- เหลือขวาเฉลี่ย < 12 จุด และมีบรรทัดยืดเต็มเกือบทั้งหมด → กระจายถูกต้อง
- บรรทัดสุดท้ายของย่อหน้าจะเหลือช่องว่างเสมอ (ถูกต้องตามหลักการพิมพ์)

## ข้อค้นพบระหว่างทดสอบ

### 1. Word แยกข้อความเป็นหลายชิ้น

ตัวแปร `{เนื้อหา}` ในไฟล์ต้นฉบับถูกเก็บเป็น **3 runs** คนละอัน:
```xml
<w:t>{</w:t>  <w:t>เนื้อหา</w:t>  <w:t>}</w:t>
```

ถ้าค้นหา `{เนื้อหา}` ใน XML ตรง ๆ จะไม่เจอ ต้องรวมทุก `<w:t>` ก่อนค้นหา

### 2. ตัวแปรต้องมี `d.` นำหน้า

ต้นฉบับใช้ `{เนื้อหา}` ซึ่งเป็นข้อความธรรมดา ไม่ใช่แท็กของ Carbone
ต้องเปลี่ยนเป็น `{d.เนื้อหา}` จึงจะถูกแทนค่า

### 3. การเปลี่ยนชื่อฟอนต์ต้องแก้ทุกจุด

ในไฟล์ต้นฉบับมีชื่อฟอนต์ **319 จุด** ที่ต้องเปลี่ยน
รวมทั้งใน `document.xml` และ `fontTable.xml`
